W4 前端三页面：React+TS+Vite 真实 API 接入、任务列表/详情/尝试详情、轮询降频、重试取消操作。
详细要求随 W1-W3 完成情况在委派前补充实际 API 字段契约。
页面结构：
A 任务列表：表格列(任务ID缩写/创建时间/状态徽章/进度条/步骤数/耗时/失败摘要/详情链接) + 顶部创建任务表单(assets 多行输入+可选故障注入开关仅演示) + 状态筛选下拉 + 手动刷新 + 自动轮询(活跃任务存在时 2s，全终态时 10s 或停)。
B 任务详情：头部状态卡(状态/reason_code/进度/创建开始结束/总耗时/取消按钮) + DAG 视图(6节点按依赖布局，CSS 定位即可，节点显状态色) + 步骤表(状态/依赖/尝试/next_retry/最近错误/输出引用/缓存命中/重试按钮) + 尝试历史区(选中步骤展开 attempts: attempt_no/worker/duration/错误/日志尾行/输出) + 事件时间线(最近 50 条)。
C 尝试详情页：全字段 + run.log 内容渲染(文本) + 输出 json 展示。
交互：加载态/空态/404 态/接口错误 toast 或横幅；操作按钮成功失败都有反馈；终态任务停高频轮询。
技术：Vite react-ts 模板、原生 CSS 变量主题、fetch 封装(处理 {ok,data|error} 包装)、无额外 UI 库。
验证：npm run build 通过 + tsc 无错；dev 起后我人工核对数据真实性(与 sqlite 查询比对)。
